# Commerce capability inventory

This is the detailed 42-category baseline for [the Shopify-style expansion plan](shopify-expansion-plan.md), using its original capability ID meanings and delivery waves. It expands every category into actions and acceptance examples. It is a scope and evidence map, not a claim of Shopify parity or feature completion. Machine-readable action rows live in [commerce-capability-inventory.json](commerce-capability-inventory.json).

## Status and evidence

Statuses use the expansion plan’s terms. **Locally verified** means the repository records local implementation evidence, not production readiness or external provider verification. **In progress** means a subset exists and acceptance remains incomplete. **Planned** means no complete implementation is evidenced. **Externally blocked** means provider access, credentials, eligibility, or legal configuration remains unverified. An empty UI/API/AI mapping means no current mapping was found.

Current UI/API evidence comes from `frontend/screens.json`, `backend/routes/api.php`, and `docs/openapi/`. Seventeen commerce tools passed explicit assistant API dispatch. The latest FunctionGemma language benchmark is 10/17; the 11/17 result recorded in the 2026-09-26 audit is historical. All 23 currently documented API operations have positive coverage evidence from the coordinator's latest run. Laravel AI SDK now mediates proposals, and /assistant screens exist in both storefronts and admin; broader model reliability remains incomplete. Provider webhooks and operation polling are infrastructure APIs, not customer assistant actions.

## Completion evidence expected per action

Before an action is marked complete, its registry row should identify its UI route (or state why UI does not apply), API method/path and versioned schemas, assistant tool and confirmation policy when relevant, permitted roles and shop guards, unit/API evidence, applicable Lean mapping, provider verification state, and remaining limitations. Provider fakes establish local behavior only. Local verification does not establish provider sandbox verification or production readiness.
